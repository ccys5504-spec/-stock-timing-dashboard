# 국내 주식 매수/매도 타이밍 분석 대시보드

관심 종목(SK하이닉스, 두산에너빌리티, 주성엔지니어링)의 매수/매도 타이밍을
기술적 지표로 분석하고 백테스트하는 Streamlit 대시보드입니다.

⚠️ **투자 참고용이며 투자 자문이 아닙니다. 실제 주문은 실행하지 않습니다.**

## 실행 방법

```bash
pip install -r requirements.txt
streamlit run app.py
```

CLI로 빠르게 백테스트 요약만 보고 싶다면:

```bash
python scripts/backtest_report.py 3   # 최근 3년 기준
```

## 차트 단위 (일봉/주봉/월봉/년봉)

"단일 종목 분석" 탭 차트 위의 **차트 단위** 라디오로 캔들차트를 일봉/주봉/월봉/
년봉으로 바꿔볼 수 있습니다. 일봉을 해당 단위로 묶어서(OHLC 재계산) 보여주고,
이평선/RSI/MACD도 그 단위 기준으로 다시 계산합니다(예: 주봉 화면의 MA20은
20주 평균).

**매수/매도 신호와 백테스트는 항상 일봉 기준 그대로**입니다 — 차트 단위를
바꿔도 신호 자체가 재계산되거나 달라지지 않습니다. 신호 마커(▲▼)는 원래
발생한 날짜 그대로 표시되니, 주봉/월봉으로 보면 그 신호가 어느 주/달에
있었는지 보는 용도로 이해하면 됩니다.

월봉·년봉은 이평선(MA60 등) 계산에 필요한 캔들 수가 조회 기간보다 많이
필요해서(연봉 MA60 = 60년치), 조회 기간이 짧으면 이평선이 안 뜨거나 캔들
자체가 몇 개 안 보일 수 있습니다 — 이 경우 사이드바에서 조회 기간을 늘리세요.

## 신호 로직

4개 지표를 각각 -1 / 0 / +1로 채점해 합산합니다.

| 지표 | 매수(+1) 조건 | 매도(-1) 조건 |
|---|---|---|
| 이동평균(20/60일) | 골든크로스 | 데드크로스 |
| RSI(14) | 30 이하(과매도) | 70 이상(과매수) |
| MACD | 시그널선 상향 돌파 | 시그널선 하향 돌파 |
| 볼린저밴드(20,2σ) | 하단 터치 후 반등 | 상단 터치 후 하락 |

합산 점수가 **임계값(기본 ±1) 이상**이면 매수/매도 신호로 판단합니다.
사이드바 슬라이더로 임계값(1~3)을 조절할 수 있습니다.

## 임계값을 ±1로 정한 이유 (실제 검증 결과)

처음에는 "지표 4개 중 2개 이상 동시에 일치"(±2)로 설계했으나, 실제 백테스트
결과 **3개 종목 모두 3년간 거래가 1번**밖에 나오지 않았습니다. 각 지표의
'크로스' 이벤트가 같은 날 동시에 겹치는 경우가 매우 드물기 때문입니다.

임계값을 ±1(지표 1개만 조건 충족해도 신호)로 낮추자, 아래처럼 "단타는 아니지만
주기적으로 매매"하는 현실적인 빈도가 나왔습니다 (2026-09-12 기준, 최근 3년):

| 종목 | 매매 횟수 | 평균 매매 주기 | 평균 보유일수 | 승률 | 전략 수익률 | 단순보유 수익률 |
|---|---|---|---|---|---|---|
| SK하이닉스 | 28회 | 약 37일에 1회 | 13일 | 68% | +163.0% | +1274.8% |
| 두산에너빌리티 | 28회 | 약 37일에 1회 | 13일 | 68% | +93.4% | +561.8% |
| 주성엔지니어링 | 35회 | 약 30일에 1회 | 12일 | 46% | +32.1% | +527.6% |

**중요**: 세 종목 모두 최근 3년간 몇 배씩 오른 강한 상승장이었기 때문에,
중간에 매도로 빠져나오는 타이밍 전략은 이 기간 기준 단순 보유보다 수익률이
낮게 나왔습니다.

### 하락장 검증 (2022년, 순수 약세장)

`scripts/backtest_range_report.py`로 하락장이었던 2022년 한 해만 따로
검증했습니다:

| 종목 | 전략 수익률 | 단순보유 수익률 | 방어 효과 |
|---|---|---|---|
| SK하이닉스 | -13.2% | -41.6% | 손실 28.4%p 축소 |
| 두산에너빌리티 | -6.6% | -26.5% | 손실 19.9%p 축소 |
| 주성엔지니어링 | -40.0% | -49.3% | 손실 9.3%p 축소 |

**3종목 모두 전략이 단순 보유보다 손실이 작았습니다.** 매도 신호로 하락
초입에 빠져나와서 폭락장을 끝까지 다 맞지 않은 효과입니다. 다만 승률
자체는 낮습니다(14~44%) — 전반적 하락 추세 속에서는 대부분의 개별 거래가
손실이지만, 손실 규모가 단순 보유보다 작다는 의미입니다.

상승장(2023~2026)과 하락장(2022) 결과를 합치면:

- **상승장**: 전략이 단순보유보다 수익률 낮음 (상승분을 다 못 먹음)
- **하락장**: 전략이 단순보유보다 손실 작음 (하락분을 덜 맞음)

즉 이 전략은 수익을 극대화하기보다는 **변동성/낙폭을 줄이는 대신 상승분의
일부를 포기하는 전형적인 추세추종형 특성**을 보입니다.

다른 기간으로 직접 검증하고 싶다면:

```bash
python scripts/backtest_range_report.py 2022-01-01 2022-12-31
```

## 거래량 필터 / 손절 규칙 (추가 튜닝)

사이드바에서 두 가지를 추가로 켤 수 있습니다.

- **거래량 필터**: 신호가 뜬 날 거래량이 최근 20일 평균의 N배(기본 1.2배) 이상일 때만
  신호를 인정합니다. 거래량이 실리지 않은 잡음성 움직임을 걸러내기 위함입니다.
  "끔 / 항상 켬 / **자동(하락장에만)**" 세 가지 방식 중 선택할 수 있습니다.
- **손절 규칙**: 매수가 대비 일정 %(기본 10%) 하락하면 매도 신호를 기다리지 않고
  즉시 청산합니다.

### 거래량 필터 "자동" 모드 — 상승장/하락장을 스스로 판별

종가가 **200일 이동평균 위**에 있으면 "상승장", 아래면 "하락장"으로 자동
판별해서, **하락장일 때만 거래량 필터를 켭니다** (상승장에서는 끄고, 하락장
에서는 켬). 임계값/거래량필터를 고정한 채 켬·끔만 따로 떼어 테스트해보니
(README 앞부분 "실제 검증 결과" 참고) 거래량 필터는 하락장 방어에는 거의
항상 도움이 됐지만 상승장 수익은 크게 깎는 경우가 많았습니다 — 그래서
"필요할 때만 켜는" 자동 모드를 만들었습니다.

최근 5년 연속 구간(상승장·하락장이 자연스럽게 섞인 기간)으로 끔/항상 켬/자동을
비교한 결과(2026-09-12 기준):

| 종목 | 끔 | 항상 켬 | 자동 |
|---|---|---|---|
| SK하이닉스 | +163.7% (MDD -38.9%) | +54.3% (MDD -41.8%) | **+173.6%** (MDD -41.1%) |
| 두산에너빌리티 | +229.1% (MDD -44.7%) | +49.5% (MDD -47.9%) | +160.6% (MDD -44.7%) |
| 주성엔지니어링 | +136.9% (MDD -53.2%) | +135.1% (MDD -47.8%) | **+323.5%** (MDD **-42.3%**) |

3종목 모두 "자동"이 "항상 켬"보다 크게 나았고, SK하이닉스·주성엔지니어링은
"끔"보다도 수익률이 높으면서 MDD까지 개선됐습니다. 이 결과를 바탕으로
**앱의 기본값을 "자동"으로 설정**해뒀습니다. (다만 3종목·5년 데이터라는
표본 한계는 여전합니다.)

`scripts/optimize.py`로 이동평균 기간(MA)·RSI 기준값·신호 임계값·거래량 필터·
손절 비율까지 **총 240개 조합**을 상승장(최근 3년)과 하락장(2022년) 양쪽에
대해 격자 탐색(grid search)해봤습니다 (종목당 약 10초, vectorbt 없이 순수
파이썬으로). 결과 요약(2026-09-12 기준):

| 종목 | 괜찮았던 조합 | 상승장 수익률 | 2022년 수익률 |
|---|---|---|---|
| SK하이닉스 | MA 20/90, RSI 25/75, 손절 없음 | +267.7% | -3.7% |
| 두산에너빌리티 | MA 10/40, RSI 35/65, 거래량필터 ON | +134.6% | **+40.3%** |
| 주성엔지니어링 | MA 30/90, RSI 25/75, 거래량필터 ON, 손절 10% | -3.2% | -14.0% |

이전(임계값/거래량/손절만 탐색, MA 20/60·RSI 30/70 고정)보다 훨씬 좋아졌습니다
— 특히 SK하이닉스와 두산에너빌리티는 이동평균 기간을 더 길게(20/90, 느린
추세추종)하거나 RSI 기준값을 완화하니 상승장 수익률과 하락장 방어력이 동시에
개선됐습니다. 주성엔지니어링은 여전히 하락장에서 손실을 완전히 못 피했지만,
손실 폭은 줄었습니다(-49.3% 단순보유 대비 -14.0%).

**참고**: 처음에는 지표 계산을 고유 조합별로 한 번만 캐싱하는 방식으로 순수
파이썬 탐색 범위를 16개 → 240개 조합으로 넓히는 데 그쳤습니다. `vectorbt`
같은 벡터화 백테스트 라이브러리를 Windows에 직접 설치하려 했으나, 이 컴퓨터의
Windows 애플리케이션 제어 정책이 새로 설치되는 numpy/scipy 네이티브 모듈을
차단해서 실패했습니다(보안 정책이라 우회 시도는 하지 않았습니다). 대신
**WSL2(Ubuntu)** 안에 별도 파이썬 가상환경을 만들어 vectorbt를 설치했더니
문제없이 동작했습니다 — 아래 "vectorbt (WSL2)" 절 참고.

## vectorbt로 더 넓은 탐색 (WSL2)

Windows 네이티브 환경에서는 vectorbt를 못 쓰지만, 이 컴퓨터에는 Docker
Desktop 덕분에 WSL2가 이미 설치되어 있었습니다. 여기에 Ubuntu 배포판과
전용 가상환경을 추가해서 vectorbt를 정상적으로 돌리는 데 성공했습니다.

```bash
# (최초 1회) Ubuntu 배포판 설치 — Windows 보안 설정은 전혀 건드리지 않음
wsl --install -d Ubuntu --no-launch

# (최초 1회) 전용 가상환경 생성 및 패키지 설치
wsl -d Ubuntu -u root -- bash -c "apt-get update -qq && apt-get install -y -qq python3-pip python3-venv python3-full"
wsl -d Ubuntu -u root -- python3 -m venv /root/vbt-venv
wsl -d Ubuntu -u root -- /root/vbt-venv/bin/pip install vectorbt "plotly==5.24.1" finance-datareader
# (vectorbt가 딸려오는 최신 plotly(7.x)와 충돌하므로 5.24.1로 맞춰야 함)

# 실행 (프로젝트 폴더를 /mnt/c/... 경로로 그대로 접근)
wsl -d Ubuntu -u root -- /root/vbt-venv/bin/python "/mnt/c/Users/<사용자명>/Desktop/AI 저작물/주식매매 타이밍/scripts/optimize_vbt.py"
```

`scripts/optimize_vbt.py`는 이동평균 단기(6종류)x장기(7종류)x손절비율(7종류)
= **294개 조합**을 종목당 약 2~3초 만에 벡터화 백테스트합니다(순수 파이썬
버전은 240개 조합에 종목당 약 10초). 결과 요약(2026-09-12 기준):

| 종목 | 최고 강건 조합 | 상승장 | 2022년(하락장) |
|---|---|---|---|
| SK하이닉스 | MA 25/50 | +494~547% | **+1.0%** (거의 무손실 방어) |
| 두산에너빌리티 | MA 5/40 | +275% | -6.8% |
| 주성엔지니어링 | MA 5/50, 손절 5% | +369% | **+2.9%** |

세 종목 모두 이전(순수 파이썬 240개 조합) 탐색보다 훨씬 강건한 조합을
찾아냈습니다 — 특히 SK하이닉스와 주성엔지니어링은 2022년 하락장을 사실상
손실 없이 통과하는 조합이 나왔습니다.

⚠️ **이 결과는 우리 앱의 4개 지표(이평선+RSI+MACD+볼린저밴드) 조합 신호와는
다른, 이동평균 골든/데드크로스 단일 전략만의 결과입니다.** 앱의 SIGNAL이 이
성적표를 그대로 내는 게 아니라는 뜻입니다. 그리고 조합 수가 240 → 294개로
늘고 더 좋은 결과가 나올수록, 과최적화 위험도 그만큼 커진다는 점은 변함없이
적용됩니다 — 오히려 "이렇게 좋은 결과가 나왔다"는 사실 자체를 의심해봐야
합니다.

### ⚠️ "수익률 극대화"에 대한 솔직한 답

과거 데이터에 대해 여러 파라미터 조합을 시험해서 "가장 성적이 좋았던 조합"을
고르는 것 자체가 **과최적화(overfitting)** 위험을 안고 있습니다. 그 조합은
이 특정 3종목, 이 특정 과거 기간에만 우연히 잘 맞았을 수도 있습니다. 그래서:

- `scripts/optimize.py`는 "가장 수익률 높은 조합"이 아니라 **상승장과
  하락장 양쪽에서 최소한 어느 정도는 버티는(강건한) 조합**을 우선순위로
  보여주도록 만들었습니다 (`robust_score = min(상승장 수익률, 하락장 수익률)`).
- 그럼에도 종목 3개, 기간 2구간이라는 작은 표본이라는 한계는 여전합니다.
  **오히려 탐색 조합이 16개 → 240개로 늘면서 과최적화 위험은 더 커졌습니다**
  — 조합이 많을수록 "우연히 이 특정 3종목·이 특정 2개 기간에만 잘 맞는" 조합을
  찾아낼 확률도 함께 올라갑니다. 진짜 "수익률 극대화"는 파라미터를 계속
  쥐어짜는 것보다, **더 많은 기간과 더 많은 종목으로 검증(walk-forward 검증)**
  하고, 극단적으로 좋아 보이는 결과는 의심하는 태도에서 나옵니다.

파라미터 탐색을 직접 돌려보려면:

```bash
python scripts/optimize.py
```

## 청산(매도) 방식 — 신호 기반 vs 트레일링 스탑 vs 적응형

"수익률을 더 극대화할 방법이 없냐"는 질문에서 출발한 기능입니다. 기존 방식은
지표가 '매도'라고 하면 무조건 파는데, 강한 상승장에서는 이게 너무 일찍 파는
셈이 되어 수익을 다 못 챙기는 구조적 한계가 있습니다. 그래서 사이드바에
**청산 방식 3가지**를 추가했습니다.

- **신호 기반 (기본)**: 매도 신호가 뜨면 바로 판다 (지금까지 쓰던 방식)
- **트레일링 스탑 단독**: 매도 신호를 무시하고, 보유 중 기록한 **최고가 대비
  일정 %(기본 20%) 하락할 때만** 판다 — 추세가 이어지는 동안은 계속 들고 감
- **적응형**: 상승장(200일선 위)엔 트레일링 스탑으로 길게 들고 가고,
  하락장엔 신호 기반으로 방어 (거래량 필터 자동 모드와 같은 아이디어)

### 실측 결과 — 트레이드오프가 뚜렷합니다 (2026-09-12 기준)

**최근 5년 연속 구간(상승장 위주):**

| 종목 | 신호 기반 | 트레일링 20% 단독 | 적응형 |
|---|---|---|---|
| SK하이닉스 | +173.6% | **+1157.9%** | +732.9% |
| 두산에너빌리티 | +160.6% | **+225.9%** | +123.0% |
| 주성엔지니어링 | +323.5% | **+406.0%** | +275.8% |

**2022년 하락장 단독:**

| 종목 | 신호 기반 | 트레일링 20% 단독 | 적응형 |
|---|---|---|---|
| SK하이닉스 | **-13.6%** | -25.1% | -18.5% |
| 두산에너빌리티 | **+20.5%** | +12.4% | +10.8% |
| 주성엔지니어링 | **-21.3%** | -42.3% | -26.7% |

**결론은 명확한 트레이드오프입니다**: 트레일링 스탑 단독은 상승장에서 수익을
몇 배로 불렸지만, 2022년 하락장에서는 3종목 모두 신호 기반보다 손실이 더
컸습니다. 적응형은 그 중간 어디쯤이지 — 어느 한쪽보다 항상 나은 게
아닙니다. **"수익 극대화"와 "손실 방어"는 같은 축의 양 끝**이라, 파라미터를
아무리 더 튜닝해도 둘 다 동시에 최대화할 수는 없습니다. 사이드바에서
본인의 위험 선호에 맞게 셋 중 하나를 직접 고르면 됩니다.

## 종목 추천 (스크리너)

관심 종목 3개에 국한하지 않고, **시가총액 상위 종목(KOSPI/KOSDAQ, 우선주·관리종목·
스팩 등은 자동 제외)을 대상으로 지금 시점에 매수/매도 신호가 뜬 종목을 찾아주는**
스크리너를 대시보드 세 번째 탭("🧭 종목 추천")에 추가했습니다.

- 시장(KOSPI/KOSDAQ), 스캔할 종목 수(시가총액 상위 20~300개)를 고를 수 있습니다
- 사이드바의 임계값/거래량 필터를 그대로 적용해서 계산합니다
- 병렬로 데이터를 가져와서 100종목 스캔에 약 20~30초 정도 걸립니다
- 매수/매도 신호가 뜬 종목을 표로 보여주고, 색상으로 구분합니다

**주의**: 이 추천은 기술적 지표를 기계적으로 계산한 결과일 뿐이며, 재무 상태·
뉴스·산업 전망 등은 전혀 반영하지 않습니다. 반드시 투자 자문이 아닌 참고
자료로만 쓰고, 실제 매매 전 직접 확인하세요. 시가총액 상위 종목 위주로만
스캔하는 이유는 거래량이 적은 소형주는 신호 신뢰도가 떨어지기 때문입니다.

CLI로 직접 스캔해보려면:

```bash
python -c "
from data.fetch import get_universe
from screener.scan import scan_signals
universe = get_universe(markets=('KOSPI','KOSDAQ'), top_n=100)
result = scan_signals(universe, years=1)
print(result[result['신호'] != '관망'])
"
```

### 스캔 결과 활용하기

- **클릭해서 상세 차트 보기**: 스캔 결과 표에서 종목 행을 클릭하면 자동으로
  "단일 종목 분석" 화면으로 이동해서 그 종목의 캔들차트/백테스트를 바로 볼 수
  있습니다. (내부적으로는 탭 대신 `st.radio` + `st.session_state`로 화면을
  전환합니다 — Streamlit의 `st.tabs`는 코드에서 활성 탭을 바꿀 수 없기 때문)
- **파일로 저장**: 스캔 결과를 CSV 또는 엑셀(.xlsx)로 다운로드할 수 있습니다.
  나중에 다른 날짜의 스캔 결과와 비교하고 싶다면 파일명에 날짜가 자동으로
  들어가니 그대로 모아두면 됩니다.
- **관심종목 교체 제안**: 현재 관심종목 3개 중 오늘 시점 점수가 가장 낮은
  종목과, 스캔 결과 중 관심종목이 아닌 종목의 최고 점수를 비교해서 교체를
  제안합니다. "교체 적용" 버튼을 누르면 `data/watchlist.json`이 실제로
  갱신됩니다(되돌리고 싶으면 파일을 직접 수정하거나 기존 값으로 다시
  교체하면 됩니다). **이 비교는 오늘 신호 점수만 보는 것이라 백테스트
  성과 기반 판단이 아닙니다** — 진지하게 종목을 바꾸기 전에는 "단일 종목
  분석"에서 그 종목의 백테스트 결과도 따로 확인하는 걸 권합니다.

### 관심 종목은 이제 코드가 아니라 파일로 관리됨

기존에는 `data/fetch.py` 안의 `WATCHLIST` 딕셔너리를 직접 고쳐야 했지만,
이제 [data/watchlist.json](data/watchlist.json) 파일로 분리되어 있어서
앱에서 교체 제안을 적용하면 바로 이 파일이 갱신됩니다. 파일이 없으면
기본값(SK하이닉스/두산에너빌리티/주성엔지니어링)으로 자동 생성됩니다.

## 내 보유종목 반영

"💼 내 보유종목" 탭에서 실제로 갖고 있는 종목의 **종목코드·수량·매입단가**를
표에 직접 입력하면:

- 현재가 기준 **평가손익(금액·%)**, 총 매입/평가금액을 바로 계산해서 보여줍니다
- 보유 종목의 **지금 시점 매수/매도 신호**를 확인할 수 있습니다
  (관심종목 3개가 아니어도 임의의 종목코드를 입력하면 됩니다)
- 보유 중인데 **매도 신호**가 뜨면 상단에 경고가 뜹니다
- 사이드바에서 손절을 켜뒀다면, 매입가 대비 손절 기준에 도달한 종목도 별도로
  경고합니다

입력한 정보는 [data/holdings.json](data/holdings.json)에 로컬로만 저장되고
어디로도 전송되지 않습니다. 증권사 API 연동이나 계좌 자동 조회는 지원하지
않습니다 — 계좌 정보·API 키는 사용자가 직접 관리해야 하는 영역이라 이 도구는
"직접 입력" 방식만 제공합니다.

## 생성되는 파일과 구글드라이브

이 프로젝트가 로컬에 만드는 것은 코드/캐시 몇백 KB 수준이라 디스크 용량
걱정은 크지 않지만, 스캔 결과를 CSV/엑셀로 계속 내려받아 쌓다 보면 파일이
늘어날 수 있습니다. 그런 파일들은 다운로드 후 Claude에게 "이 파일 구글드라이브에
저장해줘"라고 요청하면 Claude가 연결된 구글드라이브 계정으로 바로 업로드해줍니다
(Streamlit 앱 자체가 자동으로 구글드라이브에 올리게 하려면 별도의 구글 OAuth
연동 개발이 필요해서, 지금은 "다운로드 → 필요시 Claude에게 업로드 요청"이
가장 간단한 방법입니다).

## 프로젝트 구조

```
app.py                   # Streamlit 대시보드 진입점
                          # (단일 종목 분석 + 3종목 비교 + 종목 추천 스크리너 + 내 보유종목 탭)
data/fetch.py             # 시세 데이터 수집 + 시가총액 상위 종목 목록 (FinanceDataReader)
data/watchlist.json        # 관심 종목 목록 (앱에서 교체 제안을 적용하면 갱신됨)
data/holdings.json         # 내 보유종목 (종목코드/수량/매입단가, 앱에서 입력·저장)
signals/indicators.py     # 지표 계산, 매수/매도 점수, 거래량 필터 로직
backtest/engine.py        # 백테스트 엔진 (손절 규칙 포함)
screener/scan.py          # 다종목 스캔(병렬) — 종목 추천용
scripts/backtest_report.py       # CLI 백테스트 요약 (최근 N년)
scripts/backtest_range_report.py # CLI 백테스트 요약 (임의 기간, 하락장 검증용)
scripts/optimize.py              # 파라미터 격자 탐색 (MA/RSI/임계값/거래량필터/손절, 순수 파이썬)
scripts/optimize_vbt.py          # vectorbt 기반 대규모 탐색 (WSL2에서만 실행 가능)
```

## 관심 종목 수정

앱의 "종목 추천" 탭에서 교체 제안을 적용하거나, `data/watchlist.json`을 직접
편집(종목명: 종목코드 형식)하면 됩니다.
