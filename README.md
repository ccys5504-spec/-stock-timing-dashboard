## 🧺 v2: 포트폴리오(상대강도) 전략 — 실험 중 (2026-09-20 4차 갱신: 장세필터 제거, 수익 제고)

지금까지의 모든 내용(아래)은 "관심 종목 3개 중 언제 사고팔지"를 판단하는
**v1 전략**입니다. v1을 워크포워드로 검증해보니 파라미터를 아무리 튜닝해도
실전 기대수익이 낮다는 게 확인돼서(아래 "워크포워드 검증" 절), **"언제
살까"가 아니라 "무엇을 살까"를 바꾸는 v2 전략**을 별도로 실험 중입니다.
자세한 설계·변경 과정은 [PROMPT_V2.md](PROMPT_V2.md) 참고. 핵심 차이:

- 관심종목 3개 고정이 아니라, 시가총액 상위 100~300개 중 **최근 3/6/12개월
  상대강도(모멘텀) 상위 종목**을 매월 골라서 보유
- 고정 %손절 대신 **ATR(변동성) 기반** 손절/트레일링 스탑
- 종목당 전액 몰빵이 아니라 **변동성 역가중** 비중(종목당 상한 12%)
- ~~KOSPI/KOSDAQ 지수 200일선으로 장세를 판단해 하락장이면 투자비중 축소~~ →
  **2026-09-20부터 기본으로 끔**(수익을 거의 절반으로 깎고 낙폭은 못 줄였음 —
  아래 "구성요소 기여도 실험" 참고). 코드(`use_regime=True`)로는 다시 켤 수 있음
- 이미 보유 중인 종목은 순위가 크게 밀려나야만 매도(순위 이력), 사소한 비중
  차이는 리밸런싱하지 않음 — 불필요한 매매 축소
- 룩백 기간·ATR 배수 등은 **데이터에 맞춰 튜닝하지 않고 문헌 표준값으로 고정**
  (v1의 `optimize.py`가 겪은 과최적화를 구조적으로 피하기 위함)

**시행착오 요약** (전체 과정은 PROMPT_V2.md에 기록): 처음 버전은 2016-2019
같은 박스권에서 거의 이익을 못 냈습니다(-0.1%, 샤프 0.05). Wilder의
ADX(추세강도) 필터로 무추세 구간의 노출을 줄이는 수정을 추가했더니 박스권은
좋아졌지만(+9.8%, 샤프 0.42) 그 대가로 전체 기간 수익률이 단순보유보다
낮아졌습니다 — "박스권 방어 vs 전체 수익률" 중 뭘 우선할지 사용자에게
물었을 때 한 번은 "박스권 방어"를, 다시 물었을 때는 **"수익률"**을

### ⚠️ 가장 중요한 비교: "같은 종목군을 그냥 들고 있었다면"

이 전략이 고르는 종목군 자체(오늘 시가총액 상위 100개)가 코스피보다 훨씬
많이 올랐기 때문에, 코스피를 이겼다는 말만으로는 부족합니다. 진짜 비교 대상은
같은 100개를 동일가중으로 들고만 있었을 때(**+676.9%, MDD -51.0%**)입니다.
장세필터를 끄기 전 v2는 +356.7%로 그 절반 남짓이었고, **끈 뒤에는 +617.8%로
거의 따라잡으면서 낙폭은 -34.3%로 더 작습니다.** 다만 이 동일가중 수치는
**살아남은 승자만 모은 종목군이라 생존편향이 그대로 섞인 상한선**이고 비용도
뺐기 때문에 "실제로 살 수 있었던 대안"은 아닙니다 — 어느 정도가 생존편향인지는
지금 데이터로 분리할 수 없습니다.

**방향 결정 (2026-09-20, 사용자):** 6~12개월 모의투자(월말 신호 수기 기록)는
하지 않고, 방어는 손절 규칙에 맡기며, **같은 종목군에서 위험 축소보다
수익 제고를 목표로 한다.**

### 🔬 구성요소 기여도 실험 (`scripts/portfolio_ablation.py`, 2026-09-20)

수익을 깎는 요소를 찾기 위해 구성요소를 하나씩 끄거나 바꿔봤습니다(연속값을
튜닝하지 않고 켬/끔·2배 같은 소수의 이산 변형만, 전체 기간이 아니라 국면별
구간마다 확인). 상위 100개/15종목, 왕복비용 0.3%, 수익률 / MDD:

| ATR 손절 끔 | +13.1% / -15.2% | +69.2% / -15.5% | +69.1% / -22.6% | +123.7% / -47.8% | +620.4% / -47.8% |

읽는 법:
- **수익을 깎던 건 200일선 장세필터**입니다. 끄면 전체 수익이 거의 2배가 되는데
  전체 MDD는 그대로입니다(반등 초입을 놓치기만 하고 큰 낙폭은 못 막았다는 뜻).
  그래서 기본값을 "끔"으로 바꿨습니다.
- **ATR 손절은 남겼습니다.** 수익을 조금 깎지만(끄면 +620%) MDD를 -47.8%→-34.3%로
  줄여주는 사실상 유일한 방어 수단이고, "방어는 손절에 맡긴다"는 방침과 맞습니다.
  손절폭을 2배로 넓히는 건 수익도 낙폭도 나아지지 않아 채택하지 않았습니다.
- 역변동성 비중은 동일비중과 거의 차이가 없어 그대로 뒀습니다.
- **다른 설정에서도 같은 방향인지 재확인**(장세필터 켬 → 끔, 전체 수익률):
  상위200개/15종목 +319%→+631%, 100개/10종목 +196%→+349%, 100개/20종목
  +322%→+493%. 수익 개선은 일관됩니다.

**치르는 대가(숨기지 않습니다):** 2016~21 구간의 낙폭이 3~9%p 커졌고(-12.0%→-15.3%,
-10.9%→-17.0%), 박스권 2016-18은 +7.8%→+4.2%로 오히려 낮아졌으며(10종목 설정에서는
-2.3%→-6.8%), 다른 설정에서는 전체 MDD도 최대 6%p 나빠졌습니다(상위200개 -40.1%→-45.8%).
즉 **하락장에서 더 크게 흔들립니다.** 그리고 ⚠️ 종목군이 '오늘의 생존 종목'이라 하락 뒤
반등한 종목만 남아 있어, 장세필터의 방어 효과가 실제보다 **과소평가**됐을 가능성이
있습니다 — 이 개선폭 전부를 실전 기대수익으로 읽으시면 안 됩니다. 8개 변형을 4개 구간에서
비교하다 고른 것이라 이 자체도 소폭의 사후선택이 섞여 있습니다.
"순수 모멘텀 +1129.5%"는 생존편향으로 부풀려진 값이니 목표로 삼지 마세요.

(참고: ADX 필터 제거 + 순위 이력/소액생략만으로도 최초 버전(+288.3%)보다 나아졌고,
거기에 장세필터를 끄면서 수익이 한 단계 더 올랐습니다. 박스권(2016-2019)은
최초 버전(-0.1%)보다는 낫지만 장세필터를 끈 뒤로는 +4.2%로 약합니다.)

⚠️ **다만 이 비교를 너무 믿지는 마세요.** 3년짜리 구간의 샤프 비율은
표본이 작아서 추정 오차가 매우 큽니다(대략적으로 계산하면 표준오차가
±0.5~0.6 수준 — 즉 "샤프 0.39"와 "샤프 0.05"의 차이도 통계적으로는
자신 있게 다르다고 말하기 어려운 폭입니다). 이번 결과가 우연히 이 특정
역사적 경로에서 잘 나온 것일 가능성을 배제할 수 없습니다 — 워크포워드
검증에서 배운 "적은 표본으로 좋아 보이는 결과를 과신하지 말 것"이라는
교훈을 v2에도 그대로 적용해야 합니다.


각 스크립트는 시세 조회에 실패한 종목이 있으면 "요청 N개 → 실제 사용 M개"로
개수와 이름을 출력합니다(조용히 빠지는 종목이 없도록).

**다음 단계 후보:** 남은 수익 격차(동일가중 +676.9% 대비)는 ATR 손절이 상승 추세

**종목추천/오늘의 추천 화면**은 이제 스캔에 실패한 종목 수와 데이터 기준일을

### 워크포워드(walk-forward) 검증 — `scripts/walk_forward.py` (신규)

과거를 "훈련 구간(3년)"과 그 바로 다음 "검증 구간(1년)"으로 나누고,

탐색으로 고른 뒤, 훈련 때는 전혀 보지 못한 검증 구간에 그대로 적용해서

있는 성과에 훨씬 가깝습니다.

| 종목 | 검증(OOS) 평균 수익률 | 같은 기간 단순보유 평균 | 전략이 단순보유를 이긴 폴드 |
|---|---|---|---|
| SK하이닉스 | +0.9% | +61.7% | 2/7 |
| 두산에너빌리티 | +18.5% | +69.0% | 3/7 |
| 주성엔지니어링 | +1.7% | +49.5% | 5/7 |
| **전체 평균** | **+7.0%** | **+60.1%** | **10/21** |

**이걸 위 "임계값을 ±1로 정한 이유"·"거래량 필터 자동 모드"·"240개 조합
최적화" 표의 수치와 비교해보세요.** 그 표들의 수익률(예: SK하이닉스
+206.9%, 두산에너빌리티 +152.6%)은 전부 "과거 전체를 보고 고른" 최적화
수치이고, 그 조합을 **정말 몰랐던 미래에 적용했을 때**는 위 표처럼 평균
+7.0%로 훅 꺼집니다 (단순보유 +60.1%에도 크게 못 미칩니다). 이 둘의 차이가

보면 됩니다. 즉 **`scripts/optimize.py`나 위쪽 표의 "괜찮은 조합"들은
"이 특정 과거에 잘 맞았던 조합"이지 "미래에도 잘 맞을 조합"이 아닙니다** —
이 도구를 쓸 때는 이 사실을 감안해야 합니다.

"단순보유 평균 +388.9%")가 실제보다 낙관적일 가능성이 있습니다.
FinanceDataReader로는 과거 시점의 상장폐지 종목 목록을 구하기 어려워서 이
한계를 완전히 없애지는 못했습니다 — 결과를 볼 때 감안해야 합니다.

### 표준 위험지표 추가 — 샤프 비율 / 소르티노 비율 / 시장 노출도

"단일 종목 분석" 탭과 `scripts/backtest_report.py` 출력에 세 지표를
추가했습니다(`backtest/engine.py`의 `BacktestResult`). 누적수익률만 보면
변동성이 큰(운이 좋으면 크게 벌고 나쁘면 크게 잃는) 전략이 유리해 보일 수
있는데, 이 지표들은 그 위험을 같이 반영합니다.

- **샤프 비율**: 수익을 그 변동성으로 나눈 값(연율화). 높을수록 같은
  위험 대비 수익이 좋다는 뜻.
- **소르티노 비율**: 샤프와 비슷하지만 '하락 변동성'만 위험으로 계산.

  더 적합할 수 있음.
- **시장 노출도**: 전체 기간 중 실제로 주식을 들고 있었던 비율. 낮을수록
  현금으로 대기한 기간이 길었다는 뜻 — 같은 수익률이면 노출도가 낮을수록
  더 효율적이었다고 볼 수 있음.

**매수/매도 신호와 백테스트는 항상 일봉 기준 그대로**입니다 — 차트 단위를

**2026-09-18 개선**: 예전엔 월봉·년봉이 사이드바 "조회 기간"만큼만 데이터를

## 임계값을 ±1로 정한 이유 (실제 검증 결과)

처음에는 "지표 4개 중 2개 이상 동시에 일치"(±2)로 설계했으나, 실제 백테스트
결과 **3개 종목 모두 3년간 거래가 1번**밖에 나오지 않았습니다. 각 지표의
'크로스' 이벤트가 같은 날 동시에 겹치는 경우가 매우 드물기 때문입니다.

임계값을 ±1(지표 1개만 조건 충족해도 신호)로 낮추자, 아래처럼 "단타는 아니지만
주기적으로 매매"하는 현실적인 빈도가 나왔습니다 (**2026-09-15 기준, 체결
타이밍 수정 후 재산출**, 최근 3년, 거래량 필터 끔):

| 종목 | 매매 횟수 | 평균 매매 주기 | 평균 보유일수 | 승률 | 전략 수익률 | 단순보유 수익률 |
|---|---|---|---|---|---|---|

### ⚠️ "수익률 극대화"에 대한 솔직한 답

과거 데이터에 대해 여러 파라미터 조합을 시험해서 "가장 성적이 좋았던 조합"을
고르는 것 자체가 **과최적화(overfitting)** 위험을 안고 있습니다. 그 조합은
이 특정 3종목, 이 특정 과거 기간에만 우연히 잘 맞았을 수도 있습니다. 그래서:

- `scripts/optimize.py`는 "가장 수익률 높은 조합"이 아니라 **상승장과
  하락장 양쪽에서 최소한 어느 정도는 버티는(강건한) 조합**을 우선순위로
  보여주도록 만들었습니다 (`robust_score = min(상승장 수익률, 하락장 수익률)`).
- 그럼에도 종목 3개, 기간 2구간이라는 작은 표본이라는 한계는 여전합니다.
  **오히려 탐색 조합이 16개 → 240개로 늘면서 과최적화 위험은 더 커졌습니다**
  — 조합이 많을수록 "우연히 이 특정 3종목·이 특정 2개 기간에만 잘 맞는" 조합을
  찾아낼 확률도 함께 올라갑니다. 진짜 "수익률 극대화"는 파라미터를 계속
  쥐어짜는 것보다, **더 많은 기간과 더 많은 종목으로 검증(walk-forward 검증)**
  하고, 극단적으로 좋아 보이는 결과는 의심하는 태도에서 나옵니다.

파라미터 탐색을 직접 돌려보려면:

```bash
python scripts/optimize.py
```

## 청산(매도) 방식 — 신호 기반 vs 트레일링 스탑 vs 적응형

"수익률을 더 극대화할 방법이 없냐"는 질문에서 출발한 기능입니다. 기존 방식은
지표가 '매도'라고 하면 무조건 파는데, 강한 상승장에서는 이게 너무 일찍 파는
셈이 되어 수익을 다 못 챙기는 구조적 한계가 있습니다. 그래서 사이드바에
**청산 방식 3가지**를 추가했습니다.

- **신호 기반 (기본)**: 매도 신호가 뜨면 바로 판다 (지금까지 쓰던 방식)
- **트레일링 스탑 단독**: 매도 신호를 무시하고, 보유 중 기록한 **최고가 대비
  일정 %(기본 20%) 하락할 때만** 판다 — 추세가 이어지는 동안은 계속 들고 감
- **적응형**: 상승장(200일선 위)엔 트레일링 스탑으로 길게 들고 가고,
  하락장엔 신호 기반으로 방어 (거래량 필터 자동 모드와 같은 아이디어)

하루 늦어지면서 더 나은 진입 시점을 맞은 조합들이 있었던 것으로 보입니다).
트레일링 스탑 단독은 상승장에서 수익을 몇 배로 불렸지만, 2022년 하락장에서는
3종목 모두 신호 기반보다 손실이 더 컸습니다. 적응형은 그 중간 어디쯤이지
— 어느 한쪽보다 항상 나은 게 아닙니다. **"수익 극대화"와 "손실 방어"는
같은 축의 양 끝**이라, 파라미터를 아무리 더 튜닝해도 둘 다 동시에 최대화할
수는 없습니다. 사이드바에서 본인의 위험 선호에 맞게 셋 중 하나를 직접
고르면 됩니다.

## 종목 추천 (스크리너)

관심 종목 3개에 국한하지 않고, **시가총액 상위 종목(KOSPI/KOSDAQ, 우선주·관리종목·
스팩 등은 자동 제외)을 대상으로 지금 시점에 매수/매도 신호가 뜬 종목을 찾아주는**
스크리너를 대시보드 세 번째 탭("🧭 종목 추천")에 추가했습니다.

**⭐ 오늘의 추천 (2026-09-16 추가)**: 탭을 열면 스캔 버튼을 누르지 않아도
맨 위에 자동으로 뜨는 카드입니다. 시가총액 상위 100개(고정) 중 사이드바
설정(임계값·거래량 필터) 기준으로 점수가 가장 높은 매수 후보 **딱 1개**만
보여줍니다 — "하루에 하나씩만 확인하고 싶다"는 용도에 맞춘 기능입니다.
매수 신호가 하나도 없으면 그렇다고 알려줍니다(관망도 선택입니다).

아래쪽의 직접 스캔 기능도 그대로 남아있습니다:

- 시장(KOSPI/KOSDAQ), 스캔할 종목 수(시가총액 상위 20~300개)를 고를 수 있습니다
- 사이드바의 임계값/거래량 필터를 그대로 적용해서 계산합니다
- 병렬로 데이터를 가져와서 100종목 스캔에 약 20~30초 정도 걸립니다
- 매수/매도 신호가 뜬 종목을 표로 보여주고, 색상으로 구분합니다

**주의**: 이 추천은 기술적 지표를 기계적으로 계산한 결과일 뿐이며, 재무 상태·
뉴스·산업 전망 등은 전혀 반영하지 않습니다. 반드시 투자 자문이 아닌 참고
자료로만 쓰고, 실제 매매 전 직접 확인하세요. 시가총액 상위 종목 위주로만
스캔하는 이유는 거래량이 적은 소형주는 신호 신뢰도가 떨어지기 때문입니다.

CLI로 직접 스캔해보려면:

```bash
python -c "
from data.fetch import get_universe
from screener.scan import scan_signals
universe = get_universe(markets=('KOSPI','KOSDAQ'), top_n=100)
result = scan_signals(universe, years=1)
print(result[result['신호'] != '관망'])
"
```

### 스캔 결과 활용하기

- **클릭해서 상세 차트 보기**: 스캔 결과 표에서 종목 행을 클릭하면 자동으로
  "단일 종목 분석" 화면으로 이동해서 그 종목의 캔들차트/백테스트를 바로 볼 수
  있습니다. (내부적으로는 탭 대신 `st.radio` + `st.session_state`로 화면을
  전환합니다 — Streamlit의 `st.tabs`는 코드에서 활성 탭을 바꿀 수 없기 때문)
- **파일로 저장**: 스캔 결과를 CSV 또는 엑셀(.xlsx)로 다운로드할 수 있습니다.
  나중에 다른 날짜의 스캔 결과와 비교하고 싶다면 파일명에 날짜가 자동으로
  들어가니 그대로 모아두면 됩니다.
- **관심종목 교체 제안**: 현재 관심종목 3개 중 오늘 시점 점수가 가장 낮은
  종목과, 스캔 결과 중 관심종목이 아닌 종목의 최고 점수를 비교해서 교체를
  제안합니다. "교체 적용" 버튼을 누르면 `data/watchlist.json`이 실제로
  갱신됩니다(되돌리고 싶으면 파일을 직접 수정하거나 기존 값으로 다시
  교체하면 됩니다). **이 비교는 오늘 신호 점수만 보는 것이라 백테스트
  성과 기반 판단이 아닙니다** — 진지하게 종목을 바꾸기 전에는 "단일 종목
  분석"에서 그 종목의 백테스트 결과도 따로 확인하는 걸 권합니다.

- 종목코드를 URL로 넘기는 키움의 공식 방법을 확인하지 못해서(로그인이 필요한
  화면이라 검증 불가) 임의의 URL을 만들어 붙이지 않았습니다.

입력한 정보는 GitHub 비공개 Gist(설정 안 됐으면 로컬 `data/holdings.json`

방식" 절 참고. 증권사 API 연동이나 계좌 자동 조회는 지원하지 않습니다 —
계좌 정보·API 키는 사용자가 직접 관리해야 하는 영역이라 이 도구는 "직접
입력" 방식만 제공합니다.

## 데이터 저장 방식 — 재배포에도 살아남는 저장소 (2026-09-16)

Streamlit Cloud는 코드가 재배포될 때마다(새 push든 Manage app의 수동
Reboot든) 컨테이너를 완전히 새로 만듭니다. `data/holdings.json`/
`data/watchlist.json`은 개인정보라 git에 올리지 않는데(`.gitignore`),
바로 그 이유 때문에 예전엔 재배포마다 Cloud에서 직접 입력한 보유종목·
관심종목이 전부 사라지는 문제가 있었습니다.

지금은 `.streamlit/secrets.toml`에 `GITHUB_TOKEN`(gist 권한만 있는 개인
토큰)과 `GIST_ID`(비공개 Gist 하나)를 설정해두면, 관심종목/보유종목을
로컬 파일 대신 그 Gist에서 읽고 씁니다 — 재배포와 무관하게 유지됩니다.
설정이 없으면(로컬 개발 등) 예전처럼 로컬 JSON 파일로 그대로 동작합니다.

설정 방법은 [.streamlit/secrets.toml.example](.streamlit/secrets.toml.example)
참고. 로컬에 `.streamlit/secrets.toml`로 복사해서 채운 뒤, Streamlit
Cloud에도 앱 관리 화면(Manage app) → Settings → Secrets에 같은 두 줄을
붙여넣어야 Cloud에서도 적용됩니다.

## 생성되는 파일과 구글드라이브

이 프로젝트가 로컬에 만드는 것은 코드/캐시 몇백 KB 수준이라 디스크 용량
걱정은 크지 않지만, 스캔 결과를 CSV/엑셀로 계속 내려받아 쌓다 보면 파일이
늘어날 수 있습니다. 그런 파일들은 다운로드 후 Claude에게 "이 파일 구글드라이브에
저장해줘"라고 요청하면 Claude가 연결된 구글드라이브 계정으로 바로 업로드해줍니다
(Streamlit 앱 자체가 자동으로 구글드라이브에 올리게 하려면 별도의 구글 OAuth
연동 개발이 필요해서, 지금은 "다운로드 → 필요시 Claude에게 업로드 요청"이
가장 간단한 방법입니다).
